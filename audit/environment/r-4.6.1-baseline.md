## Lockfile reconciliation

The lockfile records R 4.5.0 and 226 package records. All 226 package names are
available in the R 4.6 library stack: 219 in the project library and seven
recommended packages in the R framework library. Comparing normalized package
versions found 224 exact matches and two mismatches:

| Package | `renv.lock` | Installed | Disposition |
|---|---:|---:|---|
| Matrix | 1.7-3 | 1.7-6 | Record the R 4.6.1-compatible installed version after final verification |
| sf | 1.1-1 | 1.1-2 | Record the R 4.6.1-compatible installed version after final verification |

No blanket package update was performed. In particular, the restored versions
of LightLogR, suntools, and the modelling stack agree with the lockfile.

On 2026-07-30, `renv::status()` additionally identified `shiny` as used by the
project but absent from the R 4.6 library. A source audit found no Shiny
runtime, server declaration, or Shiny API. Instead, renv 1.2.3 infers Shiny
whenever a Quarto YAML header contains a `params:` mapping; the 11
hypothesis notebooks intentionally use such parameters for batch rendering.
Shiny 1.14.0 and its imported runtime dependencies (`httpuv` 1.6.17,
`sourcetools` 0.1.7-2, and `xtable` 1.8-8) were therefore installed and will
be recorded so dependency discovery remains synchronized. They are
parameter-metadata dependencies, not an interactive analytical runtime.

Two additional optional dependencies were verified as operationally
necessary. Existing code calls `performance::check_model()`, which fails
without its plotting backend `see`; `see` 0.14.1 and its missing imports
`correlation` 0.8.8 and `modelbased` 0.16.0 were installed. For non-Gaussian
models, performance otherwise silently changes its default from simulated to
ordinary residual diagnostics when `DHARMa` is absent. DHARMa 0.5.0 and its
required dependency closure were installed so the planned glmmTMB
distributional checks use simulated residuals. Synthetic linear and Poisson
glmmTMB diagnostics now pass with warnings treated as errors. None of these
packages has yet been written to `renv.lock`; the final lockfile snapshot
remains gated on the complete clean run.

The lockfile header fixes the restore repository at
`https://cloud.r-project.org`, but existing package records mix the labels
`CRAN`, Posit Package Manager `cran/latest`, and `RSPM`. The current project
activation resolves `CRAN` to `https://cloud.r-project.org`; packages installed
during this repair retained their binary repository label `RSPM`. The final
snapshot must use one explicit repository policy and retain package source
metadata. A dated repository snapshot would be preferable to a floating
`latest` URL when a suitable R 4.6.1 binary snapshot is available.

Unbounded `renv::status()` calls were observed to run indefinitely; two
orphaned diagnostics had each consumed a CPU core for more than nine hours
before being terminated. A project `.renvignore` now limits dependency
discovery to authored R/Quarto source, tests, and audit scripts while
excluding generated renders, binary artifacts, data, submission staging, and
the project library. Interim checks use deterministic lock-versus-library and
dependency comparisons. The deterministic audit currently completes
`renv::dependencies()` in roughly two seconds and records 57 unique packages;
its machine-readable outputs are in `audit/environment/`.
This scan is fast, but it does not prove which later internal phase made the
former status calls pathological. The mandatory final status check will be
invoked only after the lock is ready, through a child-process timeout that
retains stdout, stderr, exit status, timing, and timeout metadata.

## Verification commands

The initial restore was run separately from analysis execution:

```sh
RENV_PATHS_SANDBOX=/private/tmp/codex-renv-sandbox-nathealth \
RENV_CONFIG_CACHE_ENABLED=FALSE \
Rscript -e 'options(renv.config.install.verbose = TRUE); renv::restore(prompt = FALSE)'
```

A clean-session package-load check can be repeated with:

```sh
NH_RENV_LIB="$PWD/renv/library/macos/R-4.6/aarch64-apple-darwin23"
R_LIBS_USER="$NH_RENV_LIB" Rscript --vanilla -e '
  options(warn = 1)
  packages <- c(
    "LightLogR", "suntools", "lme4", "glmmTMB", "mgcv",
    "performance", "see", "DHARMa", "emmeans", "gratia",
    "itsadug", "ordinal", "nnet", "sf", "rmarkdown", "knitr"
  )
  stopifnot(getRversion() == "4.6.1")
  for (package in packages) {
    library(package, character.only = TRUE)
  }
  print(sessionInfo())
  print(sf::sf_extSoftVersion())
'
```

The repeatable project smoke test is:

```sh
R_PROFILE_USER=/dev/null \
R_LIBS_USER=renv/library/macos/R-4.6/aarch64-apple-darwin23 \
Rscript --vanilla tests/test_environment_smoke.R
```

It verifies the runtime and key namespaces, a `see`-backed linear diagnostic,
a DHARMa-simulated Poisson glmmTMB diagnostic, sf linkage, and the
Quarto/Pandoc executables.

The repeatable, repository-offline reconciliation is:

```sh
R_PROFILE_USER=/dev/null \
R_LIBS_USER=renv/library/macos/R-4.6/aarch64-apple-darwin23 \
Rscript --vanilla scripts/environment/run_environment_audit.R .
```

It compares static declarations, optional runtime dependencies, the installed
library stack, exact lock entries, the R version, and recorded source and
repository metadata without calling `renv::status()` or a repository.

Only after the gated snapshot, run the mandatory status check through the
timeout-controlled wrapper. The second argument is the wall-clock limit in
seconds and the third controls renv's source-metadata check:

```sh
R_PROFILE_USER=/dev/null \
R_LIBS_USER=renv/library/macos/R-4.6/aarch64-apple-darwin23 \
Rscript --vanilla scripts/environment/run_renv_status_safe.R . 300 true
```

The wrapper writes retained output and metadata under
`audit/environment/renv-status/`. Its timeout behavior has been verified on a
harmless sleeping child process; the project status call has deliberately not
been run at this stage.

## Snapshot gate

Do not snapshot `renv.lock` at this stage. The lockfile may be updated only
after every canonical notebook runs from a clean session, mandatory artifacts
are regenerated, all working HTML renders pass, and the single final
manuscript DOCX passes its submission-stage checks. The intended
minimal snapshot is R 4.6.1 with Matrix 1.7-6 and sf 1.1-2; all other package
records should remain fixed unless a documented compatibility or verified
runtime requirement requires a change. The verified additions described
above—Shiny's parameter-metadata closure, `see`, and DHARMa with their required
closures—must be explicitly recorded even where renv's static scanner cannot
infer an optional runtime dependency.
