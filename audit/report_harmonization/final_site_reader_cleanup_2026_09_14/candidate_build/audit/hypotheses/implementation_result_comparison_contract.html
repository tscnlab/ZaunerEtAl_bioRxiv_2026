How each hypothesis will be compared

Nature Health hypothesis review

Last modified:

August 1, 2026

Purpose

This document retains the substantive comparison requirements shared across the hypothesis audits. H01 and H02 keep the review structure already in use. H03 through H11 use the staged workflow in H03-H11_gated_workflow.qmd, which distributes these requirements across separate audit, implementation-comparison, standalone reader-facing, and pipeline-provenance documents, with an optional production-computation gate between implementation and reader-facing results. The descriptive analysis is outside that workflow.

In H03–H11 audit documents, V0 analysis is the short name for the analysis that produced the submitted manuscript. The final reader-facing hypothesis documents do not use that term.

The main question for each hypothesis is:

How do the analysis method, numerical results, and defensible claim after audit differ from those in the submitted analysis?

Comparison with the preregistration remains mandatory, but is reported in a separate section. The submitted analysis, rather than the preregistration, is the reference for the direct audit discussion.

A separate gap-timing-unaware dataset sensitivity applies the same new H01–H11 implementation to the primary dataset and to the predefined comparison dataset, with only objectively demonstrable data errors corrected. It isolates data-preparation changes and does not rerun the submitted modelling implementation. Its rules are fixed in manuscript_prepared_data_sensitivity.md.

At first reader-facing use, explain that the gap-timing-unaware dataset still passed the general 50%-per-hour and 80%-per-day coverage rules, but the timing of the remaining missing observations is not used for an additional metric-specific adjustment. For contrast in that first explanation only, the primary dataset may be described as something that could be interpreted as a time-sensitive primary metric dataset. It is called simply the primary dataset thereafter. Internal identifiers may retain historical names for provenance; visible Stage 3 and Stage 4 labels follow REPORT-010.

Site names, order and colours

Every hypothesis uses the submitted manuscript’s site names, ordering and colour mapping in visible prose, tables, legends, facets and figures. The authoritative mapping is config/site_display_registry.csv and its full rules are recorded in site_display_conventions.md.

Missing sites are omitted without changing the order or colours of the sites that remain. Internal data codes and model reference coding are unaffected. When the shared German colour would make a figure ambiguous, use direct labels, shapes or line types in addition to—not instead of—the registered colour.

Required comparison content

H01 and H02 retain the comparison order already in use. For H03–H11, the following content is distributed across the gated documents rather than forced into one page:

  1. the question and exact comparison being estimated;
  2. what the manuscript reported;
  3. the main analysis;
  4. a direct submitted-versus-main table covering magnitude, direction, uncertainty, statistical conclusion, analytical sample, and claim;
  5. the gap-timing-unaware dataset sensitivity using the same new implementation for both datasets;
  6. the reason for every method or data-preparation change;
  7. diagnostics and other registered sensitivities;
  8. relation to the preregistration; and
  9. verification status, decisions still needed, and conditions that require a new review.

A preregistered method is never substituted for the method represented in the manuscript merely because the two differ.

Files used to record the comparisons

hypothesis_implementation_audit.csv records one row for each hypothesis, comparison being estimated, analytical role, sensor placement, and analysis scenario. It identifies the submitted and main-analysis code and output files and records why the method stayed the same or changed. The gap-timing-unaware scenario points to the same new model implementation as the main scenario and to a different prepared-data artifact.

hypothesis_result_comparisons.csv records one row per exact result, contrast, model comparison, or conclusion about a fitted curve. It retains the numerical values rather than relying only on qualitative summaries.

hypothesis_data_sensitivity_comparisons.csv records the same new implementation fitted to the primary and gap-timing-unaware datasets, including both exact model samples, their common sample, intervals, multiplicity fields, diagnostics, and stability classification.

hypothesis_comparison_status.csv tracks whether each H01–H11 HTML page has completed its method, result, claim, preregistration, and verification sections.

The existing result_differences.csv remains the detailed record for preparation and metric changes. In that file, the field baseline_value stores the value from the submitted analysis, never a preregistered value. Hypothesis-level rows link to these detailed differences where relevant rather than duplicating them.

Method comparison

The method comparison explicitly covers:

  • which data release and file were used, how rows were matched, and any correction to source records;
  • sensor placement and analysis scenario;
  • inclusion rules and the denominator used to calculate a proportion;
  • outcome, predictor, contrast, transformation, and unit;
  • whether the analysis concerns participants, participant-days, hours, or individual observations, and how repeated observations are handled;
  • the assumed outcome distribution and scale, the fixed and random model terms, and how correlation between observations—including observations close together in time—is handled;
  • the set of related tests adjusted together for multiple testing and the adjustment method;
  • checks of model fit, influential observations, and whether model fitting completed stably; and
  • code, fitted-model file, result table, figure, and the exact data used to produce the figure.

The gap-timing-unaware dataset sensitivity must use the same new analysis implementation as the main analysis. Only its prepared-data input differs. Each correction made to the gap-timing-unaware dataset has an identifier and evidence locator. A model cannot be simplified only for this sensitivity.

For every multiple-testing correction, the hypothesis page must state which single test is selected from each outcome model before the results are examined. Individual coefficients and follow-up contrasts are not automatically added to the same set of tests.

Exact formula display

Every H01–H11 audit page must contain a visible, evaluated R code cell that prints the exact Wilkinson formula objects supplied to the fitting functions. The display must include the selected model and every fitted model used in a likelihood, Wald, score, AIC, or other model-structure comparison, including full, reduced, null, and sensitivity models.

The displayed formulas must be generated from the same formula-building function or recovered directly with stats::formula() from the fitted model; a separately typed mathematical equation is explanatory but does not satisfy this requirement. A generic response ~ ... formula may represent several outcomes only when their right-hand side, random effects, smooths, offsets, and correlation structure are identical. If any of these differ, each distinct formula must be shown and linked to its model ID.

Wilkinson notation does not encode the response distribution, link, estimation method, contrasts, or residual-correlation settings. Those must be shown immediately beside the formula output and remain in the model manifest. The formula cell and manifest must agree exactly before a hypothesis audit can be marked complete.

Pilot before a computation-heavy bootstrap

Every computation-heavy bootstrap or simulation must first run a separate 50- or 100-replicate pilot with the proposed production code. The pilot is used to verify failure handling, checkpointing, output tables and figures, and to estimate the duration and resource needs of the full run. It is labelled as non-inferential and cannot supply manuscript values or claims.

Before the full run starts, the hypothesis task must show the pilot output, report successful and failed replicates, provide a reasoned full-runtime range and expected completion time, and obtain explicit author confirmation. Any code, diagnostic or display repair requires another pilot. The complete rule and the exception for the H01 run already underway are recorded in bootstrap_execution_policy.md.

Each difference is assigned a change_class. none is an affirmative result and means that the submitted method was reproduced and retained. A change is not called a repair unless the evidence and verification justify that classification.

Result comparison

The direct submitted-versus-main table records, where applicable:

  • the exact fitted-model counts—not counts from the prepared dataset—for participants, participant-days, hours, 30-minute observations, other observations, and sites;
  • valid measurement hours used to derive a participant-day or participant-level outcome, clearly separated from observations that entered the fitted model;
  • category counts, including category × site counts when an interaction or sparse-cell decision is involved;
  • exact common-sample counts, where a common sample means that both analyses use the same participants, participant-days, or time-resolved observations;
  • estimate, standard error, confidence interval, raw and adjusted (p)-values, the set of related tests adjusted together, and the result’s position within that set;
  • changes in direction, uncertainty, statistical significance, or conclusion;
  • the submitted manuscript claim and the main-analysis claim; and
  • links to the exact submitted and main-analysis code and output files.

The accompanying data-sensitivity table repeats the result using the same new H01–H11 implementation on the gap-timing-unaware dataset. It reports both model samples, their exact common sample, estimates and 95% confidence intervals, raw and adjusted (p)-values, diagnostics, and a stability classification.

P-value display

Every displayed raw or adjusted p-value follows REPORT-008: use a leading zero and exactly three decimal places, show values strictly below 0.001 as <0.001, and use bold type only when that displayed value meets its explicitly labelled significance rule. Raw and adjusted values are labelled separately. Full numeric precision remains in CSV and model artifacts; display rounding is never used to decide significance. The shared helper is scripts/pipeline/p_value_display.R.

The numerical values take precedence over a qualitative label. A difference is described as negligible or material only when a practical margin was declared before the comparison. Otherwise it is not_classified_no_margin.

Paired near-eye and chest comparison

Each Stage 3 report applies REPORT-009. When separately fitted near-eye and chest estimates exist for the identical paired/common sample, outcome, predictor, contrast, model structure, transformation, and scale, show their relationship with near-eye on the horizontal axis, chest on the vertical axis, an identity line, null lines, and equal axis geometry. Component intervals may appear in an adjacent table when including them in the plot would be illegible.

Do not compare unmatched all-available samples in this display or treat closeness to the identity line as equivalence. When a scalar comparison would be invalid, state why and use a matched curve, contrast plot, coefficient plot, or concise table instead. Retain paired source data, an informative caption, and alt text.

Preregistration section

The preregistration section reports whether the audited analysis is aligned, clarified, an approved deviation, an unapproved deviation, not specified, ambiguous, could not be estimated as registered, or not applicable. It links to the preregistration summary and deviation register, while remaining separate from the submitted-versus-audited comparison.

When author approval is needed

Author approval is required before adopting a change to the comparison being estimated, inclusion rule, metric, statistical model, set of tests adjusted together, substantive result, preregistration interpretation, or manuscript claim. A hypothesis review cannot be completed until:

  • its submitted method and result are recoverable or explicitly marked otherwise;
  • its primary and gap-timing-unaware sensitivity code and output pass a run in a fresh R session;
  • every correction to the gap-timing-unaware dataset passes the data-fidelity rule or is removed;
  • method and result rows are complete and linked;
  • relevant diagnostics and sensitivities are classified;
  • consequential manuscript claims are linked to verified results; and
  • mandatory checks are PASS.

A change in an earlier preparation or analysis step requires every affected hypothesis to be reviewed again.
