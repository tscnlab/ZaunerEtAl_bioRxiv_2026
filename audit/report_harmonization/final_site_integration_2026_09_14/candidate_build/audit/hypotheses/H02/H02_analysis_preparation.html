From verified 30-minute data to reported results

Last modified:

August 14, 2026

About this analysis record

The scientific question was whether daily patterns of melanopic equivalent daylight illuminance (melEDI) differed among sites and whether differences among people within sites were larger than the differences among sites. The near-eye sensor position was primary because it measures light closer to the eye, but it is not a direct retinal measurement. The chest sensor position was analysed separately as complementary evidence and is not a measure of ocular exposure.

A participant-day is one participant’s observations on one local calendar date. Participant-day counts therefore describe repeated recorded days, not additional independent participants.

This page explains which data and code produced the reported H02 result, why each analytical step was needed, and what evidence shows that the processing and model behaved as intended. The companion H02 results report presents the scientific findings.

NoteHow to use this provenance page

This page explains the input and sample checks, model construction, model checks, and links between analysis code and accepted stored outputs. Rendering verifies file identities. A model frame is the exact set of rows and variables used for one fitted model. Rendering also calculates descriptive summaries from the H02 model frames. It does not fit a model, estimate an autocorrelation parameter, calculate model predictions, rerun a bootstrap, or recompute a Shapley allocation; those results are read from the listed output files. The result report lists the H02 preregistration deviations.

1. Data entering the analysis

Verifying the source files

The analysis starts from named, versioned files rather than an informal copy of the data. The function h02_validate_inputs() in scripts/hypotheses/H02/h02_contract.R compares the current files with pinned SHA-256 identities and checks the relevant base and temporal-provenance manifest rows. Every fitting and figure-building script performs this check before proceeding.

Two prepared datasets enter the analysis. The primary dataset could be interpreted as a time-sensitive primary metric dataset because its preparation uses the timing of remaining missing observations where that timing is relevant to the metric. The predefined sensitivity is the gap-timing-unaware dataset. It still passed the general 50%-per-hour and 80%-per-day coverage rules, but the timing of the remaining missing observations was not used for an additional metric-specific adjustment. This name does not mean that gaps, missingness, or coverage were ignored.

What the source data already contain

The source files already contain 30-minute arithmetic-mean melEDI, coverage and admissibility information, local dates and wall-clock bins, and participant/site identifiers. H02 does not recalculate these measurements. It joins them to verified true-time provenance so that local wall time can describe the daily profile while true UTC controls observation ordering.

The primary dataset admitted a 30-minute bin when at least 15 one-minute melEDI values were valid. Unsupported bins remained missing; they were not converted to darkness. The support audit below is an output of build_h02_model_data.R, not a calculation introduced for this document.

2. Fitted samples and model frames

Code and purpose

scripts/hypotheses/H02/build_h02_model_data.R sources two function modules:

  • h02_contract.R fixes the input identities, model specification, scenario registry, transform, and reproducible seeds;
  • h02_data.R validates keys, joins temporal provenance, creates the fitted support, defines residual-sequence starts, and constructs the all-available and placement-matched samples.

The script writes eight H02-only frames: two preparation rules × two placements × two sample definitions. The all-available near-eye frame is the primary sample. The all-available chest frame is complementary. The placement-matched frames retain only participant-day clock bins available for both placements and are sensitivity analyses, not a pooled model.

Within each frame, participant identifiers are prefixed by site, and participant-day identifiers combine site, participant, and local date. Rows are ordered using verified true elapsed time within those groups; local wall-clock time remains the coordinate used to describe the daily profile.

Why the response was transformed

The fitted response is \log_{10}(\mathrm{melEDI}+0.1\ \mathrm{lx}). The offset retains exact-zero observations and maps them to −1. The transformation compresses a range that extends from darkness to tens of thousands of lux, but it does not make the zero mass disappear. Because this discrete spike is much taller than any bin among the positive measurements, combining both in one histogram hides the shape of the positive distribution. The figure therefore reports the number and percentage of exact zeros separately and uses its vertical scale for positive melEDI observations only.

The accepted descriptive values are retained in the frozen positive-observation source data and exact-zero summary.

3. Response transformation and nonlinear model construction

Exact selected formula

H02 used a nonlinear GAM analysis. A generalized additive model (GAM) allows the association with local clock time to bend across the day rather than forcing it to follow a straight line. The fitted response is log10(melEDI + 0.1 lx); a back-transformed curve applies the inverse transformation and returns to melEDI in lux.

scripts/hypotheses/H02/h02_modeling.R contains the fitting functions; h02_contract.R supplies their fixed specification. The exact Wilkinson formula was:

response ~
  s(time_hour, bs = "cc", k = 12) +
  s(time_hour, site, bs = "sz", k = 12) +
  s(time_hour, participant, bs = "fs", k = 10) +
  s(participant_day, bs = "re")

The first smooth is the global time effect, the site-average daily curve: it gives every site equal weight and joins smoothly at midnight. The sz term estimates site-specific departures that sum to zero, so no site is treated as the reference. The participant factor smooth represents remaining differences in daily shape among people after the time and site patterns are considered. The participant-day random effect represents remaining day-to-day level shifts within a participant after those patterns are considered; it moves an entire fitted day up or down.

Only the global time effect is forced to join at midnight in the primary model. A sensitivity analysis also makes the site and participant deviations cyclic.

How the selected model was applied

The primary near-eye model is fitted first by run_h02_analysis.R. Reduced versions without the site pattern, participant pattern, or participant-day intercept are fitted with the same estimated AR parameter to compare model structures. The full structure is retained, and the identical selected structure is then applied to the other seven H02 frames. Each scenario estimates its own boundary-aware AR parameter from its preliminary residuals.

For every fitted scenario, the script writes the selected model, a checkpoint, site-curve predictions, fitted term contributions, residual summaries, and the stored 2,000-draw hierarchical variation bootstrap. The following fit table is read from model_fit_summary.csv; no fit is performed here.

4. Ordering and residual dependence

Why local time and true time are both needed

Autocorrelation means that adjacent 30-minute residuals can remain more alike than residuals farther apart. The AR(1) structure represents this correlation as strongest for adjacent observations and weaker at longer lags. It must restart wherever two observations are not part of the same continuous recorded sequence.

Local wall-clock time answers the scientific question about time of day. It cannot by itself establish elapsed ordering across daylight-saving folds, gaps, or missing bins. h02_data.R therefore carries the verified true-UTC source-bin links into each model frame, orders observations by true elapsed time, and defines a new residual sequence:

  • at the start of every participant-day;
  • after a missing or otherwise discontinuous 30-minute interval; and
  • on both sides of a wall-clock outcome that has no one-to-one elapsed-time coordinate.

The table is read from the recorded boundary check. “Continuous” rows are ordinary observations inside an existing sequence and are included only to make the denominator visible.

5. From fitted models to reported quantities

Site curves and pointwise intervals

h02_modeling.R and h02_figure4_pointwise.R evaluate the stored model on a common 48-bin clock grid. The global time effect is the site-average curve, an average across sites that gives every site equal weight. A site curve is that global effect plus the site’s sum-to-zero departure. Participant and participant-day terms are set to their reference contributions when constructing site curves. A pointwise 95% confidence interval (95% CI) describes uncertainty at one displayed clock time. It comes from the fitted linear-predictor matrix and coefficient covariance with smoothing parameters held fixed; it is not a simultaneous band for the full day and does not multiplicity-control every red segment. The plotted curves are back-transformed to melEDI in lux for reader interpretation.

build_h02_figure4_replication.R applies the same builder to near-eye and chest models. It reads stored fits and contributions; it does not refit the model. Its principal outputs are:

  • artifacts/10_figures/H02/figure4_exact_layout_replication.png;
  • artifacts/10_figures/H02/figure4_exact_layout_replication_chest.png;
  • matching PDF files; and
  • artifacts/11_source_data/H02/figure4_exact_layout_source*.rds.

Fitted-curve variation

For every scenario, run_h02_analysis.R extracts the fitted global, site, participant, and participant-day contributions. It then calculates precisely defined curve-dispersion summaries on the modelling scale. Within-site participant and day summaries use site-average weighting, so every site contributes equally.

The stored 95% intervals resample sites, participants within sites, and participant-days within participants 2,000 times. The fitted contributions remain fixed. Thus, the bootstrap describes cluster-sampling uncertainty conditional on the fitted smooth structure; it is not a model-refitting bootstrap. The stored resampling draws are under artifacts/08_diagnostics/H02/*__variation_bootstrap.rds.

Shapley allocation of fitted-model relevance

run_h02_dominance_analysis.R is intentionally narrower: it runs only for the main all-available near-eye and complementary chest samples. The global time effect is mandatory in all subset models. The script fits every one of the eight possible combinations of site pattern, participant pattern, and participant-day shift, then allocates their increments in row-weighted in-sample R^2 across all orders of entry. This Shapley allocation is the average contribution of a component across all orders in which the components could be added, so shared fitted-model information is allocated rather than counted repeatedly. The implementation is also recorded technically as exact general dominance.

The 2,000-draw hierarchical bootstrap resamples clusters while holding the eight sets of fitted predictions fixed. The calculation is descriptive in-sample relevance, not causal importance and not cross-validated predictive importance. Stored results and execution evidence are under:

  • artifacts/09_tables/H02/dominance_*.csv;
  • artifacts/11_source_data/H02/*__dominance_predictions.rds;
  • artifacts/08_diagnostics/H02/*__dominance_bootstrap.rds; and
  • artifacts/12_manifests/H02/H02_dominance_manifest.csv.

How to examine or reproduce H02

A reader can examine the analysis in four passes:

  1. inspect h02_contract.R and input_hashes.csv to confirm the frozen input files and model specification;
  2. compare the descriptive samples and support displays above with sample_counts.csv and the model-frame RDS files;
  3. follow the producing script named in each output manifest, checking that its recorded inputs and outputs match the quantity being estimated; and
  4. read the H02 results report alongside the result tables, model-check outputs, and source-data objects rather than attempting to infer results from a figure image alone.

Changes to source data or processing rules should be made before the hypothesis-specific model frames are built and then propagated to every affected analysis. Changing H02 alone would otherwise break comparability with the other hypotheses. Alternative H02 model choices should remain clearly labelled sensitivity analyses until their estimands and model checks are established.

## About this analysis record

The scientific question was whether daily patterns of **melanopic equivalent
daylight illuminance (melEDI)** differed among sites and whether differences
among people within sites were larger than the differences among sites. The
near-eye sensor position was primary because it measures light closer to the
eye, but it is not a direct retinal measurement. The chest sensor position was
analysed separately as complementary evidence and is not a measure of ocular
exposure.

A **participant-day** is one participant's observations on one local calendar
date. Participant-day counts therefore describe repeated recorded days, not
additional independent participants.

This page explains **which data and code produced the reported H02 result, why
each analytical step was needed, and what evidence shows that the processing
and model behaved as intended**. The companion
[H02 results report](../../../notebooks/hypotheses/H02.qmd) presents the
scientific findings.

extends from darkness to tens of thousands of lux, but it does not make the
zero mass disappear. Because this discrete spike is much taller than any bin
among the positive measurements, combining both in one histogram hides the
shape of the positive distribution. The figure therefore reports the number

## 3. Response transformation and nonlinear model construction

### Exact selected formula

H02 used a **nonlinear GAM analysis**. A generalized additive model (GAM)
allows the association with local clock time to bend across the day rather
than forcing it to follow a straight line. The fitted response is
`log10(melEDI + 0.1 lx)`; a **back-transformed** curve applies the inverse
transformation and returns to melEDI in lux.

`scripts/hypotheses/H02/h02_modeling.R` contains the fitting functions;
`h02_contract.R` supplies their fixed specification. The exact Wilkinson
formula was:

```r
response ~
  s(time_hour, bs = "cc", k = 12) +
  s(time_hour, site, bs = "sz", k = 12) +
  s(time_hour, participant, bs = "fs", k = 10) +
  s(participant_day, bs = "re")
```

The first smooth is the **global time effect**, the site-average daily curve:
it gives every site equal weight and joins smoothly at midnight. The `sz` term
estimates site-specific departures that sum to zero, so no site is treated as
the reference. The participant factor smooth represents remaining differences
in daily shape among people after the time and site patterns are considered.
The participant-day random effect represents remaining day-to-day level shifts
within a participant after those patterns are considered; it moves an entire
fitted day up or down.

Only the global time effect is forced to join at midnight in the primary
model. A sensitivity analysis also makes the site and participant deviations
cyclic.

## 4. Ordering and residual dependence

### Why local time and true time are both needed

**Autocorrelation** means that adjacent 30-minute residuals can remain more
alike than residuals farther apart. The AR(1) structure represents this
correlation as strongest for adjacent observations and weaker at longer lags.
It must restart wherever two observations are not part of the same continuous
recorded sequence.

Local wall-clock time answers the scientific question about time of day. It
cannot by itself establish elapsed ordering across daylight-saving folds,
gaps, or missing bins. `h02_data.R` therefore carries the verified true-UTC
source-bin links into each model frame, orders observations by true elapsed
time, and defines a new residual sequence:

- at the start of every participant-day;
- after a missing or otherwise discontinuous 30-minute interval; and
- on both sides of a wall-clock outcome that has no one-to-one elapsed-time
  coordinate.

The table is read from the recorded boundary check. “Continuous” rows are
ordinary observations inside an existing sequence and are included only to
make the denominator visible.

## 5. From fitted models to reported quantities

### Site curves and pointwise intervals

`h02_modeling.R` and `h02_figure4_pointwise.R` evaluate the stored model on a
common 48-bin clock grid. The global time effect is the **site-average curve**,
an average across sites that gives every site equal weight. A site curve is
that global effect plus the site's sum-to-zero departure. Participant and
participant-day terms are set to their reference contributions when
constructing site curves. A **pointwise 95% confidence interval (95% CI)**
describes uncertainty at one displayed clock time. It comes from the fitted
linear-predictor matrix and coefficient covariance with smoothing parameters
held fixed; it is not a simultaneous band for the full day and does not
multiplicity-control every red segment. The plotted curves are back-transformed
to melEDI in lux for reader interpretation.

`build_h02_figure4_replication.R` applies the same builder to near-eye and
chest models. It reads stored fits and contributions; it does not refit the
model. Its principal outputs are:

- `artifacts/10_figures/H02/figure4_exact_layout_replication.png`;
- `artifacts/10_figures/H02/figure4_exact_layout_replication_chest.png`;
- matching PDF files; and
- `artifacts/11_source_data/H02/figure4_exact_layout_source*.rds`.

### Fitted-curve variation

For every scenario, `run_h02_analysis.R` extracts the fitted global, site,
participant, and participant-day contributions. It then calculates precisely
defined curve-dispersion summaries on the modelling scale. Within-site
participant and day summaries use site-average weighting, so every site
contributes equally.

The stored 95% intervals resample sites, participants within sites, and
participant-days within participants 2,000 times. The fitted contributions
remain fixed. Thus, the bootstrap describes cluster-sampling uncertainty
conditional on the fitted smooth structure; it is not a model-refitting
bootstrap. The stored resampling draws are under
`artifacts/08_diagnostics/H02/*__variation_bootstrap.rds`.

### Shapley allocation of fitted-model relevance

`run_h02_dominance_analysis.R` is intentionally narrower: it runs only for
the main all-available near-eye and complementary chest samples. The global
time effect is mandatory in all subset models. The script fits every one of
the eight possible combinations of site pattern, participant pattern, and
participant-day shift, then allocates their increments in row-weighted
in-sample $R^2$ across all orders of entry. This **Shapley allocation** is the
average contribution of a component across all orders in which the components
could be added, so shared fitted-model information is allocated rather than
counted repeatedly. The implementation is also recorded technically as exact
general dominance.

The 2,000-draw hierarchical bootstrap resamples clusters while holding the
eight sets of fitted predictions fixed. The calculation is descriptive
in-sample relevance, not causal importance and not cross-validated predictive
importance. Stored results and execution evidence are under:

- `artifacts/09_tables/H02/dominance_*.csv`;
- `artifacts/11_source_data/H02/*__dominance_predictions.rds`;
- `artifacts/08_diagnostics/H02/*__dominance_bootstrap.rds`; and
- `artifacts/12_manifests/H02/H02_dominance_manifest.csv`.

### How to examine or reproduce H02

A reader can examine the analysis in four passes:

1. inspect `h02_contract.R` and `input_hashes.csv` to confirm the frozen input
   files and model specification;
2. compare the descriptive samples and support displays above with
   `sample_counts.csv` and the model-frame RDS files;
3. follow the producing script named in each output manifest, checking that its
   recorded inputs and outputs match the quantity being estimated; and
4. read the H02 results report alongside the result tables, model-check outputs, and
   source-data objects rather than attempting to infer results from a figure
   image alone.

Changes to source data or processing rules should be made before the
hypothesis-specific model frames are built and then propagated to every
affected analysis. Changing H02 alone would otherwise break comparability with
the other hypotheses. Alternative H02 model choices should remain clearly
labelled sensitivity analyses until their estimands and model checks are
established.

::: {.callout-tip title="Reader takeaway"}
The H02 result was not generated inside a single opaque notebook. It came from
a verified set of source files, H02-only model frames, a reusable temporal-model
implementation, separately recorded inference and model checks, stored
cluster-bootstrap evidence, and checksummed outputs. This page shows how those
pieces connect without changing the reported scientific result.
:::
