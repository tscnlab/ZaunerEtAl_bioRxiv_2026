Preparation 02: Assess coverage and document sample flow

From aligned one-minute measurements to eligible participant-days

Last modified:

August 13, 2026

Purpose and position in the analysis chain

Preparation 02 evaluates whether the aligned one-minute records from Preparation 01 contain enough valid melEDI to represent an hour or a complete participant-day. It reads the stored near-eye and chest files separately, constructs a complete local-clock grid for every participant-date present in those files, and records hourly and daily coverage decisions. The accepted outputs enter Preparation 03 for reference-profile learning and Preparation 04 for metric derivation.

The primary dataset uses the full 1,440-minute hybrid measurement day, including bedside sleep-environment measurements. A day passes when at least 80% of those minutes have valid melEDI. The 50% hourly rule is applied only when an hourly summary is needed; a failed hour does not erase its observed minutes from the daily decision or from minute-based metrics.

The separately predefined gap-timing-unaware dataset still passed the general 50%-per-hour and 80%-per-day coverage rules. Its name means that the timing of remaining missing observations was not used for an additional metric-specific adjustment. For contrast, the primary dataset could be interpreted as a “time-sensitive primary metric dataset.” This report presents the general coverage step for the primary dataset; the separate dataset is constructed and identified later in the preparation chain.

1. The decisions applied

Coverage uses melEDI as the common availability signal. Illuminance retains its own missingness, so an unavailable melEDI value does not erase an observed illuminance value. Table 1 separates the hourly and daily decisions and shows when each affects later use.

The daily denominator differs from the preregistered sleep-excluded denominator. Sleep-excluded rules remain prespecified sensitivities; they are not substituted for the primary decision on this page. Preparation 04 later checks whether the timing and amount of remaining support are adequate for each specific metric. This primary full-day denominator choice is documented in DEV-055.

2. Overall input and retained coverage

No observation ordered in actual time is deleted. Coverage decisions are stored as flags and eligible signal columns. The aligned values, raw values, time variables, and sleep/wear provenance remain available in the placement files.

The primary day rule retained 816 of 1,136 near-eye participant-days and 902 of 1,249 chest participant-days. The corresponding eligible files contain 1,131,060 valid near-eye melEDI minutes and 1,253,505 valid chest melEDI minutes. Near-eye and chest measurements remain separate throughout.

3. Coverage by site

Table 3 shows both the numerator and denominator at each site. “Days retained by direct daily rule” are days that reached 80% coverage across the day but would have failed if sub-50% hours had first been discarded. The direct daily rule retained seven such near-eye days and eight such chest days.

Daily valid melEDI fractions were not concentrated only near the 80% boundary. Their stored distribution ranged from near-zero coverage to complete coverage, with medians of 94.7% for near-eye days and 95.8% for chest days.

4. Why measurements were unavailable

The stored missing-data records distinguish a missing one-minute record, an observed record whose signal was unusable, an otherwise passing day with only zero melEDI values, and a day below 80% valid melEDI. These categories can overlap: missing readings are the underlying event, while hourly or daily failure is a consequence for a later summary.

Five otherwise passing days were excluded by the flat-zero screen: two near-eye and two chest days at Izmir (TR), plus one chest day at Delft (NL). Individual zero readings remain valid measurements, and the inclusive sensitivity flag remains stored for those days.

5. Sample flow through each branch

The full sample-flow file reports each step both overall and by site. Table 6 shows the overall branches without treating actual-time rows, local-clock rows, and valid signal minutes as interchangeable denominators.

The all-zero-inclusive and hour-screened rows are stored comparisons, not the primary dataset. They do not replace the accepted direct daily rule.

6. Checks that passed

NoteWhat is calculated during this render?

This report reads the stored coverage manifest, settings, hourly decisions, daily decisions, reason-coded missing-data periods, and sample-flow table. During rendering it checks file identities and required columns and calculates only compact descriptive summaries of those stored rows. It does not construct a participant-day grid, reassess an hour or day, change a coverage flag, rebuild a coverage file, derive a metric, or run the production verifier.

```{r}
      paste(missing_columns, collapse = ", ")
    )

  if (!is.null(source_note)) {
    output <- output |>
      gt::tab_source_note(gt::md(source_note))
```

## 1. The decisions applied

Coverage uses melEDI as the common availability signal. Illuminance retains
its own missingness, so an unavailable melEDI value does not erase an observed
illuminance value. @tbl-preparation02-rules separates the hourly and
daily decisions and shows when each affects later use.

```{r}
#| label: tbl-preparation02-rules
#| tbl-cap: "Coverage and plausibility decisions recorded in Preparation 02."

coverage_rules |>
  prep_gt() |>
  gt::cols_width(
    Decision ~ gt::pct(20),
    Requirement ~ gt::pct(36),
    `Scientific consequence` ~ gt::pct(44)
  )
```

The daily denominator differs from the preregistered sleep-excluded
denominator. Sleep-excluded rules remain prespecified sensitivities; they are
not substituted for the primary decision on this page. Preparation 04 later
checks whether the timing and amount of remaining support are adequate for
each specific metric.
This primary full-day denominator choice is documented in [DEV-055](../preregistration_deviations.qmd#dev-055).

## 2. Overall input and retained coverage

No observation ordered in actual time is deleted. Coverage decisions are
stored as flags and eligible signal columns. The aligned values, raw values,
time variables, and sleep/wear provenance remain available in the placement
files.

```{r}
#| label: tbl-preparation02-overall
#| tbl-cap: "Overall inputs and stored coverage outcomes by measurement placement."

settings_display |>
  prep_gt() |>
  gt::fmt_integer(columns = c(`Near-eye`, Chest), use_seps = TRUE) |>
  gt::cols_width(
    `Stored outcome` ~ gt::pct(60),
    `Near-eye` ~ gt::pct(20),
    Chest ~ gt::pct(20)
  )
```

The primary day rule retained 816 of 1,136 near-eye participant-days and 902
of 1,249 chest participant-days. The corresponding eligible files contain
1,131,060 valid near-eye melEDI minutes and 1,253,505 valid chest melEDI
minutes. Near-eye and chest measurements remain separate throughout.

## 3. Coverage by site

@tbl-preparation02-site-days shows both the numerator and denominator at
each site. “Days retained by direct daily rule” are days that reached 80%
coverage across the day but would have failed if sub-50% hours had first been
discarded. The direct daily rule retained seven such near-eye days and eight
such chest days.

```{r}
#| label: tbl-preparation02-site-days

site_day_summary |>
```

with medians of 94.7% for near-eye days and 95.8% for chest days.

## 4. Why measurements were unavailable

The stored missing-data records distinguish a missing one-minute record, an
observed record whose signal was unusable, an otherwise passing day with only
zero melEDI values, and a day below 80% valid melEDI. These categories can
overlap: missing readings are the underlying event, while hourly or daily
failure is a consequence for a later summary.

```{r}
#| label: tbl-preparation02-gaps
#| tbl-cap: "Continuous missing or unusable periods and daily coverage consequences."

gap_summary |>
  prep_gt(
    source_note = paste0(
      "An hour below 50% is not labelled as a gap because its observed ",
      "one-minute values remain available for daily and minute-based metrics."
    )
  ) |>
  gt::fmt_integer(
    columns = c(
      `Continuous periods`,
      `Participant-days`,
      `Local-clock minutes`,
      `Longest period (minutes)`
    ),
    use_seps = TRUE
  ) |>
  gt::cols_label(
    `Continuous periods` = "Periods",
    `Participant-days` = "Days",
    `Local-clock minutes` = "Minutes",
    `Longest period (minutes)` = "Longest (min)"
  ) |>
  gt::cols_width(
    Placement ~ gt::pct(12),
    `Recorded reason` ~ gt::pct(31),
    Signal ~ gt::pct(13),
    gt::everything() ~ gt::pct(11)
  )
```

Five otherwise passing days were excluded by the flat-zero screen: two
near-eye and two chest days at Izmir (TR), plus one chest day at Delft (NL).
Individual zero readings remain valid measurements, and the inclusive
sensitivity flag remains stored for those days.

## 6. Checks that passed

::: {.callout-note appearance="simple" title="What is calculated during this render?"}
This report reads the stored coverage manifest, settings, hourly decisions,
daily decisions, reason-coded missing-data periods, and sample-flow table.
During rendering it checks file identities and required columns and calculates
only compact descriptive summaries of those stored rows. It does not construct
a participant-day grid, reassess an hour or day, change a coverage flag,
rebuild a coverage file, derive a metric, or run the production verifier.
:::

```{r}
#| label: tbl-preparation02-validation
#| tbl-cap: "Validation outcomes recorded for the accepted Preparation 02 outputs."

  prep_gt() |>
  gt::fmt_markdown(columns = Evidence) |>
  gt::cols_width(
    Check ~ gt::pct(23),
    `Stored outcome` ~ gt::pct(52),
    Evidence ~ gt::pct(25)
  )
```
