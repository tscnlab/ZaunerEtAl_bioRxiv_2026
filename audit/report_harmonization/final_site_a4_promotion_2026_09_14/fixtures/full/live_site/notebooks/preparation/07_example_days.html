Preparation 07: Inspect example days from each study site

A display-only check of prepared one-minute light exposure, daylight, diary periods, and declared non-wear

Last modified:

August 14, 2026

Purpose and position in the preparation chain

This final preparation page is a display-only inspection of the prepared one-minute data. It shows one participant-day from each study site before any hypothesis model is fitted. The profiles combine melanopic equivalent daylight illuminance (melEDI; lx), local daylight, diary-defined periods, and declared non-wear so that readers can see what the accepted minute-level records look like.

The exact scientific inputs are the prepared near-eye minute data from Preparation 02, the site- and date-specific daylight context assembled in Preparation 06, and the site metadata used to interpret local time. The fixed selection and its display files are illustrative only: none enters an H01–H11 model. Hypothesis analyses receive their stored inputs from Preparation 06, so there is no hypothesis-analysis handoff from this page.

Inputs and selection requirements

A participant-day could enter the selection pool only if it passed the general coverage rules from Preparation 02: at least 50% valid observations within each summarized hour and at least 80% valid observations across the full 24-hour day. It also needed all 1,440 local-clock minutes and one complete diary sleep interval with a visible sleep start and wake transition. One day per site was then selected reproducibly; the selection was not repeated to find especially tidy or favourable profiles.

The 80% daily rule covers the complete 24-hour measurement cycle. It combines near-eye measurements while participants were awake with bedside measurements during the diary-defined sleep interval. Retaining both contexts preserves the full day; it does not imply that the bedside sleep measurement was made at the eye.

Selected participant-days

The two compact tables separate timing from data availability so that neither has to be compressed into narrow cells. Submitted site names, order, and colour markers come from config/site_display_registry.csv.

The valid share ranges from 82.2% to 100.0%. All nine selected days therefore remain above the 80% daily threshold. A zero melEDI value is a measurement and remains visible. Declared non-wear and other unavailable minutes remain missing, so the exposure line is not connected across them. The 50% hourly rule governs hourly summaries; it does not erase an observed one-minute value from this inspection.

How to read the one-minute profiles

  • Civil night is the shaded part of the day when the Sun is more than 6° below the horizon; the unshaded interval is civil day.
  • The strip below zero shows the diary-defined waking daytime, the three hours before sleep, and sleep. Red overwrites the strip where the wear log records “off” outside diary-defined sleep; wear-log entries do not define sleep.
  • The dashed step is a contextual reference rather than a fitted value: 250 lx during waking daytime, 10 lx during the three hours before sleep, and 1 lx during sleep.
  • All panels use the same transformed y-axis so that zero, dim exposure, and high daytime exposure can appear together. The transformation changes only display spacing; the source CSV retains the stored melEDI values in lx.

One-minute profiles

The exact 12,960 rows shown below are available as the paired figure source-data CSV. For this HTML page, those stored source data are split into three three-panel figures so that axes, times, participant labels, and annotations remain readable at the final display width.

Technical provenance and checks on the current stored bundle

NoteWhat is calculated during this render?

This report reads the stored selection, settings, one-minute figure source data, display manifest, and site display registry. It calculates lightweight counts for the tables and redraws the profiles from the stored source-data CSV for a more readable page layout. It does not repeat the selection, rebuild an accepted file, recalculate a metric, or fit a model. File-identity checks are described in the technical provenance section.

Production and verification scripts

The display has its own narrow production workflow so that an illustrative choice cannot silently alter the prepared data. The producer reads accepted inputs and writes only display artifacts. The independent verifier is kept in a separate module and does not source the producer, allowing it to reconstruct the selection and compare the stored outputs by a different route.

Current bundle checks

The production verifier is designed to reopen the prepared inputs, reproduce the fixed-seed selection, and compare the selected minutes, state masks, daylight context, and figure files. That result-producing verifier was not run for this documentation render. The table below is intentionally narrower: it reports only file identity, the sealed site/daylight equivalence evidence, schema, and lightweight structural checks performed on the current bundle while this page rendered.

Stored display artifacts and analytical handoff

All six display artifacts were produced by scripts/pipeline/prepared_day_showcase.R with R 4.6.1, LightLogR 0.10.3, and ggplot2 4.0.3. Their current byte sizes and SHA-256 fingerprints match the manifest. The complete production display is stored as PNG and vector SVG.

These artifacts document and visualize already prepared data. They do not change an exposure value, state assignment, inclusion decision, sample, model frame, or hypothesis result, and they are not inputs to the hypothesis analyses.

assert_columns <- function(data, required, label) {

      label,

      paste(missing_columns, collapse = ", ")

## Purpose and position in the preparation chain

This final preparation page is a **display-only inspection** of the prepared
one-minute data. It shows one participant-day from each study site before any
hypothesis model is fitted. The profiles combine melanopic equivalent daylight
illuminance (melEDI; lx), local daylight, diary-defined periods, and declared
non-wear so that readers can see what the accepted minute-level records look
like.

The exact scientific inputs are the prepared near-eye minute data from
Preparation 02, the site- and date-specific daylight context assembled in
Preparation 06, and the site metadata used to interpret local time. The fixed
selection and its display files are illustrative only: none enters an H01–H11
model. Hypothesis analyses receive their stored inputs from Preparation 06,
so there is no hypothesis-analysis handoff from this page.

## Inputs and selection requirements

A participant-day could enter the selection pool only if it passed the general
coverage rules from Preparation 02: at least 50% valid observations within
each summarized hour and at least 80% valid observations across the full
24-hour day. It also needed all 1,440 local-clock minutes and one complete
diary sleep interval with a visible sleep start and wake transition. One day
per site was then selected reproducibly; the selection was not repeated to
find especially tidy or favourable profiles.

The 80% daily rule covers the complete 24-hour measurement cycle. It combines
near-eye measurements while participants were awake with bedside measurements
during the diary-defined sleep interval. Retaining both contexts preserves the
full day; it does not imply that the bedside sleep measurement was made at the
eye.

## How to read the one-minute profiles

- Civil night is the shaded part of the day when the Sun is more than 6°
  below the horizon; the unshaded interval is civil day.
- The strip below zero shows the diary-defined waking daytime, the three hours
  before sleep, and sleep. Red overwrites the strip where the wear log records
  “off” outside diary-defined sleep; wear-log entries do not define sleep.
- The dashed step is a contextual reference rather than a fitted value: 250 lx
  during waking daytime, 10 lx during the three hours before sleep, and 1 lx
  during sleep.
- All panels use the same transformed y-axis so that zero, dim exposure, and
  high daytime exposure can appear together. The transformation changes only
  display spacing; the source CSV retains the stored melEDI values in lx.
