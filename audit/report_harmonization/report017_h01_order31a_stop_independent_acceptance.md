## Finding classification

### H01-31A-SEM-001: confirmed shared gt HTML accessibility defect

The original duplicate-ID finding is valid but incomplete. The independent
scope audit in
`scripts/report_harmonization/check_h01_gt_accessibility_scope.R` establishes:

- 109 document-level duplicate ID names occur 720 times, giving 611 excess
  occurrences;
- every repeated ID occurs inside a native gt table and no ID repeats within
  any single table;
- 33 of 36 tables nevertheless have invalid explicit header associations;
- 3,275 of 4,798 body cells contain at least one token in `headers` that does
  not resolve to an ID inside the same table; and
- a minimal gt 1.3.0 table independently reproduces the cause: a column named
  `Model unit` renders the header ID as `Model-unit` but the body-cell
  reference as `headers="Model unit"`.

This is a technical accessibility and HTML-semantics defect in the current gt
1.3.0 rendering path. It is not an H01 scientific, value, or native-table
construction defect. A page-wide exception based only on the absence of
within-table duplicates would be unsafe because the explicit `headers`
relationships are also broken.

The first exploratory audit stopped because it assumed every existing
`headers` token would resolve within its table. The corrected audit separates
cross-table ID duplication from within-table header resolution and passes all
stated counts under R 4.6.1 with xml2 1.6.0, rvest 1.0.5, and gt 1.3.0.

Requested coordinator disposition: authorize a separately bounded shared
HTML-semantic remedy or another verified accessible construction. Its
acceptance test must establish unique IDs across the complete document and
require every explicit `headers` token to resolve exactly once to the intended
header in its own table. It must preserve every table value, row and column
order, caption, note, style, scientific artifact, and native gt source
endpoint. No package installation, package update, or lockfile edit is
proposed.
